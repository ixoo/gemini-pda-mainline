Observation
-----------

Both separate one-message reads returned success and changed their distinct
receive prefills to the same CPU-visible byte, 0x05. All four I2C6 counters
advanced by exactly four while the accepted boot ID, CPU set, handoff, and USB
service state remained unchanged.

Analysis
--------

The result is a stable ordinary-read overwrite, unlike Photon's combined WRRD
sentinel preservation. It rejects the broad hypothesis that every I2C6 receive
buffer always remains equal to its userspace prefill.

It does not establish that DA9214 register 0x05 contains 0x05. The observed
byte equals the preceding pointer byte. A post-runtime review of privately
retained Renesas Datasheet Revision 3.4, pages 36-37, confirms that the chip
permits either a repeated START or a STOP followed by a second START for this
read shape. A STOP-protocol failure is therefore not a supported explanation.
A true device response and pointer-byte controller, APDMA, cache, or buffer
residue remain alternatives. Controller DMA-start and IRQ counters are
supporting transfer evidence, not independent proof of the wire byte or
RX-DMA completion.
