Source and binary review
------------------------

The Buildbox pre-build gate re-ran both parent and child validators. It proved
generic secondary completion and public `cpu_down` source byte-identical and
compared the complete `mt6797_a72_cpu9_boot` function text byte-for-byte. The
initial one-second and following two-second sample delays remain pinned.

The child System.map contains the new global
`mt6797_a72_hps_down_snapshot`; the exact parent does not. The child contains
exactly one pair-v3 pass format, one inherited pair-v2 sample format, two
pair-v2 fault formats, one bounded first-HPS format, and no generic down-veto
format. The exact parent pair-v2 pass format is absent from the child.

Focused disassembly proves:

- the sample-3 success path calls the snapshot immediately before its terminal;
- the snapshot loads publication state, executes `dmb ishld`, then loads first
  CPU, first error, and total count;
- HPS uses exclusive load/store for both count and `0 -> -1` first-claim state;
- the winning path stores first error/CPU, executes `dmb ishst`, publishes `1`,
  and only then emits the inherited one-shot text;
- HPS action and sampler binaries are distinct from the exact parent as
  required, while all inherited symbols remain present.

Linked disassembly text for inherited functions is address-distinct because
the added global function and format shift linked addresses. It is not used to
claim source changes; the exact pre-build source comparisons above own that
invariant.

down path do not grow. The snapshot is a leaf with zero reported static stack.

Decision
--------

Accept the exact child Image.gz-dtb for deterministic offline Android-v0
container construction from the inherited known-good ramdisk. This compile is
not a boot candidate and authorizes no device action. Container identity,
header/extent validation, reproducibility, and a new predeclared runtime map
must pass before guarded boot2 deployment.
