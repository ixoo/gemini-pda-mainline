Compile and comparison review
-----------------------------

- Buildbox compiled both child and exact terminal parent with the pinned GCC
  6.3/binutils 2.28 toolchain. No native VM build ran.
- Both configuration deltas are exactly ANBOX normalization plus the retained
  observer, one-way CPU8, and CPU9 cluster-reuse options.
- Child and parent compiler diagnostics are byte-identical. The single retained
  line is the known vendor baseline diagnostic, not a child-only warning.
- The source gate rejected all 11 mutations before compilation and proved exact
  identity for generic CPU completion, public CPU-down, HPS policy, and the
  CPU9 PSCI startup function.
- Child System.map contains `mt6797_a72_coh_ipi` and
  `mt6797_a72_coh_workfn`; the exact parent contains neither.
- Focused child disassembly contains three `dmb ishld` acquire barriers and two
  `dmb ishst` release barriers in the bounded IPI callback.
- The child contains complete pair-v4 pass and fault terminals with every
  inherited pair/HPS field and all bounded coherency fields. The exact parent
  contains pair-v3 and no pair-v4 marker.
- Both stack-usage archives contain 2,484 compiler records. Child stack use is
  64 bytes for `mt6797_a72_coh_workfn`, 16 bytes for
  `mt6797_a72_coh_ipi`, and 160 bytes for the extended
  `mt6797_a72_hold_workfn`; the parent terminal worker uses 112 bytes.
- Package SHA256SUMS and the Buildbox job record validated successfully.

Acceptance boundary
-------------------

The exact child image is accepted only as input to deterministic Android-v0
container construction and offline container validation. Before device access,
the container checksum and embedded kernel identity must be fixed, deployment
must resolve inactive `boot2` from the live GPT, and the unique pair-v4 runtime
terminal plus watchdog recovery evidence must be predeclared. CPU_OFF, altered
HPS policy, a changed power boundary, and an unchanged-artifact repeat remain
out of scope.
