Gate corrections and binary review
----------------------------------

The first run compiled both variants but published no bundle after the gate
requested a standalone disassembly for the private CPU9 boot helper, which GCC
had inlined. A corrected run accepted the compile, and its manual review found
stronger durable anchors than HPS. The final c82acf7 run therefore requires and
compares cpu_psci_cpu_boot and __cpu_up for child and parent; both differ and
both are captured in the validated bundle.

The compiled CPU9 branch checks CPU 9, consumes the one-shot state, requires
CPU8 online, CPU9 offline, accepted CPU8 PSCI state, and published cluster
state, then makes one indirect standard PSCI call with CPU9's logical-map
entry and secondary_entry. It records the lifecycle result and accepted state
without replaying cluster preparation. The generic CPU-up caller accepts CPUs
8 or 9, passes the actual CPU identity and online bit to the shared completion
owner, and suppresses the vendor fatal path only for those retained A72 CPUs.

The child contains the CPU9 state/failure marker and the exact three-sample
pair terminal:

  gemini-a72-pair-v1 result=pass sample=3 cpu8=8 cpu9=9 online8=1 online9=1 hits8=3 hits9=3

The exact baseline contains no CPU9 child globals or pair marker.

  cpu_psci_cpu_boot: 128 bytes child, 128 parent
