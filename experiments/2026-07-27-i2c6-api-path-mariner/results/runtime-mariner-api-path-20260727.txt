Observation
-----------

Both ordinary i2c-dev reads returned success and produced their respective
preceding pointer bytes:

`3c -> 06` and `a6 -> 47`.

The `3c,a6` bytes existed only in userspace. They did not initialize either
zeroed kernel receive buffer. All four I2C6 counters advanced exactly by four
while boot ID, CPU set, handoff, and USB service state remained unchanged.

Analysis
--------

The pointer-echo signature survives i2c-dev's zeroed receive buffer and the
I2C core's separate zeroed DMA-safe bounce buffer. A successful no-write path
predicted `00,00`; the observed `06,47` therefore cannot be explained by
unchanged userspace prefills or by direct `I2C_RDWR` DMA-safe buffers alone.

This favors a lower controller/APDMA source such as pointer/FIFO residue,
DMA direction/address/length programming, or completion ordering. It does not
identify the physical writer, prove a wire byte, or isolate the exact
controller/APDMA defect.

The expected live tuple `d0,c0` was not observed. Values `06,47` are
pointer-correlated fault output, not DA9214 register contents.
