Exact runtime stimulus
----------------------
Natural Gemian policy supplies the only trigger by requesting CPU8 through the
normal hotplug path. There is no userspace trigger and no synthetic load. The
first CPU8 request on the boot may run the compiled discriminator once. It
must return -ECANCELED after recording one terminal result. Every later CPU8
request must return -EALREADY before hardware-owner operations. Every CPU9
request must return -EPERM. CPU8 and CPU9 must remain offline.

The first runtime action after exact identity validation is passive observer
retrieval. Do not write CPU online controls, alter HPS/PPM, run a load pulse,
suspend, re-arm the observer, access register/SMC/I2C controls, or request
CPU9. Copy the observer before optional USB/power reporting and require a
second byte-identical copy after two seconds for every terminal state.

What the owner should expect
----------------------------
The eventual guarded installer must run only from ordinary known-good Gemian.
After a verified logical-boot2 write it will shut the device down and will not
reboot. The owner then manually selects boot2.

The candidate will retain the exact Gemian ramdisk, command line, and root
filesystem, so its screen and userspace should look like ordinary Gemian.
USB/netcat and console service may be delayed. White or grey screen behavior,
an apparent reboot, or familiar Gemian visuals are not kernel identity. The
selected candidate is established only by the full boot2 checksum, running
build identity, and ABI-v3 observer header.

Expected exact rolled-back record
---------------------------------
The header must be:

  abi=mt6797-a72-transition-observer-v3 state=rolled-back count=30 overflow=0 up_tx=U down_tx=0

U must be nonzero. All records must target CPU8 and share that transaction;
there must be no CPU9, down transaction, or overflow. In timestamp order the
records must prove:

1. one HPS CPU8-up begin;
2. entry clock, secure, DCM, DA921x, two SPM, and TOPRGU checks;
3. exact SPM-reset release, TOPRGU assertion, BUCKB enable and settled readback;
4. the pre-isolation injection marker;
5. BUCKB disable, two SPM rollback checks/updates, and TOPRGU deassertion;
6. exact final DA921x, two SPM, TOPRGU, secure, DCM, and clock checks;
7. the five-component fixed final snapshot; and
8. one rolled-back terminal record.

The final state must equal the entry contract: DA921x page 0x80, BUCKB off,
VSEL 0x46; SPM 0x218=0x00010132 and 0x290=0x2; TOPRGU bit 11 clear; secure
and DCM zero; clock fields equal; CPU8/9 offline. There must be no
external-isolation clear, SRAM-LDO, PSCI CPU_ON/raw result, DCM enable, iDVFS,
secondary-online, CPU9, or later A72 boundary record.

- frozen-protocol, frozen-overflow, wrong count/order, CPU9, forbidden phase,

  attribution and prohibit another attempt pending review.
- wait-up or capture-up with no terminal record: preserve as incomplete and do
  not stimulate or repeat unchanged.

Result to next action
---------------------
- Exact rolled-back: return to ordinary Gemian, verify known-good identity,
  record the evidence, and close only the pre-isolation BUCKB/reset rollback

- Any other state: return to ordinary Gemian when safely possible, preserve

identity. If the shell is unavailable, do not improvise a remote power action;
the owner may physically select Gemian. A reboot is recovery, not proof that
