## Question or hypothesis

Can three default-off logical patches implement the audit-selected nested P30
finalizer and exactly one injected owner publication while leaving all physical
sources, production replay authority, hardware effects, and CPU requests
absent?

The positive result requires one P30-lock-spanning non-sleeping callback, exact
owner revalidation, a fully prepared scalar destination, health publication
last, and repeat rejection before the source callback.

## Safety assessment

This phase is hardware-free. It adds no production caller, physical reader,
production replay source, DT enablement, MMIO, SMC, I2C transaction, provider
operation, P30 prepare, CPU_ON, CPU_OFF, boot artifact, device access, or
partition write.

Only injected KUnit may exercise the publication function. The CPU-up gate
must remain `-EOPNOTSUPP` after injected publication, the MT6797 CPU boot
method must remain `-EAGAIN`, and CPU disable must remain false. No boot
candidate is defined.

## Analysis

The finalizer clears the logical claim only while retaining the private P30
raw lock, then invokes one callback that may take only `a72_state_lock`. This
prevents `prepare()` from entering before the callback returns and removes a
fallible release after a successful owner commit.

The publisher retains CPU-hotplug and transition ownership across locked
direct capture, A34 evaluation, P30 claim, and finalization. It has no
production caller. Its final callback byte-compares the pristine owner,
prepares every scalar before mutation, clears only the diagnostic A34 blocker,
and writes `AVAILABLE` last.

## Conclusion

The three normal patches are generated, exactly replayed, strictly checked,
and admitted to the canonical series. The exact atomic mechanism compiles and
its eight cases pass, but the first profile run is not a complete proof because
it also registered an unrelated inherited suite that cannot safely execute on
the KUnit stack. No hardware-support claim or boot candidate is defined.
