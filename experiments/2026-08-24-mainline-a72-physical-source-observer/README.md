## Question

Can one candidate-only observer collect the four existing read-only physical
sources under the direct compositor's CPU-hotplug and A72 owner locks while
preserving an all-or-zero result and proving whether execution entered and
returned from the one BigiDVFS call?

## Hypothesis

Yes. The observer can retain the three bound device references, register one
exact synchronous source callback, call the public direct snapshot once, and
unregister before releasing the references. The callback can read platform,
DA921x, and clock state, commit `before-bigidvfs`, make one BigiDVFS backend
call, commit `after-bigidvfs`, and only then mark the source record valid.

## Safety

This stage generates source patches and then runs injected hardware-free KUnit
tests. Generation and QEMU perform no physical I2C, MMIO, retained-memory
write, SMC, provider transaction, owner mutation, publisher call, CPU action,
boot-image construction, device access, or partition write. The candidate DTS
is review input only until the hardware-free proof passes and a separate
candidate is selected.

## Procedure

1. Verify the clean pushed repository and exact managed source through `0349`.
2. Generate five logical patches: ledger, observer, binding, candidate DTS,
   and focused tests.
3. Replay the patches and run semantic plus strict style validation.
4. Admit the generated bytes canonically and add one isolated KUnit profile.
5. Build that exact commit on Buildbox and run only the four injected tests in
   no-network arm64 QEMU.
6. Record pass/fail before selecting any device candidate.

Commands after this input is signed and pushed:

```sh
./scripts/buildbox generate-a72-physical-source-patches
./scripts/buildbox fetch-a72-physical-source-patches
```

## Current result

The exact current Buildbox parent and edited-file hashes have been audited.
The first generation attempt stopped on a source-validator assumption about an
adjacent C string literal. After that validator was corrected, all semantic
and replay checks passed and strict checkpatch stopped only on its
`SPLIT_STRING` warning for the two atomic retained records. That warning is now
the one explicitly scoped checker exception, matching the existing retained
ledger precedent. A third attempt then stopped on ordinary strict line-wrap
checks in the new observer before reaching its test patch; every declaration
and call with that pattern has been mechanically corrected in both files.
A fourth attempt confirmed those checks were gone and then stopped on the
continuation columns for the same nine argument lists. Most calls are now
single-line and every remaining continuation aligns with its opening
parenthesis; the test template received the same complete alignment pass. A
fifth attempt then enforced the final kernel convention: tabs must cover the
aligned portion and spaces only the remainder. All production and test
continuations now use that exact tab-plus-space form. Patch generation remains
pending. There is no boot candidate and no device action.
