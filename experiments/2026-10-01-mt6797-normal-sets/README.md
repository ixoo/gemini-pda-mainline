# Frame and submit selected normal configuration sets

The [retained normal-command owner](../2026-10-01-mt6797-normal-owner/README.md) preserves the capability result and 25 remaining TC4 pages, but has no API for the selected post-capability set commands. [Patch 0059](../../patches/proposals/0059-wifi-mediatek-frame-selected-normal-sets.patch) frames only source-identified command IDs and exact payload lengths. [Patch 0060](../../patches/proposals/0060-wifi-mediatek-submit-selected-normal-sets.patch) exposes a serialized, bounded PIO sender using that same ledger. A transport error poisons the session. Success means PIO submission, not firmware acceptance or application.

The caller still owns command order, payload provenance, regulatory policy, calibration admission and radio state. This profile introduces no caller, firmware command sequence or RF action. Its fragment changes only the local version; earlier profile series remain unchanged. A Buildbox compile is pending a clean pushed checkout, and no device test has been run for this profile. Wi-Fi support is not demonstrated.

[Focused host tests](tests/) exercised the exact two-patch result on the prepared 0058 predecessor, including configuration framing refusals, persistent post-START ownership and port-0 handling. They used synthetic payloads and a mocked HIF, not the physical controller. The [host receipt](results/host-validation.json) records source hashes and validation limits. The experiment [source contract](../2026-09-05-mt6797-wifi-contract/NORMAL_COMMAND.md) and private calibration analysis remain prerequisites for any actual command sequence.
