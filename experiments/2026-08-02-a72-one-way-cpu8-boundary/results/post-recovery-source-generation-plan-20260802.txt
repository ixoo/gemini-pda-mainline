Corrected watchdog boundary
---------------------------
The first natural HPS request is already executing when cpu_psci_cpu_boot is
entered. The implementable and safety-relevant boundary is therefore not
"before the userspace or HPS request" but "inside the serialized CPU8 boot
callback, before the first A72 hardware mutation or PSCI request." The normal
CPU-hotplug writer serialization is already held at that point. The takeover
wrapper must acquire the ordinary kicker lock, stop future kicks, arm the exact
low-level reset-only owner, and restore normal kicks only if ownership never
began. It must not recursively disable CPU hotplug from inside the hotplug path.

Logical generated patch plan
----------------------------
1. Add the one-way terminal ABI and reuse the accepted observer/owner helpers.
2. Add a CPU8-specific watchdog takeover wrapper around the runtime-proven
   TOPRGU recovery owner, composed with the normal kicker lock.
3. Add owner-local SRAM-LDO request/readback and MP2 DCM enable/readback helpers.
   SRAM success requires two stable secure reads, exact selector low state
   0x8fb for the 110000 request, and a stable calibration word; never expose the
   calibration value in a public marker or result.
4. Replace the vendor CPU8 preparation branch with the modeled one-shot
   orchestrator. CPU9 rejects before action. Pre-isolation failure unwinds only
   exact owned state; any isolation-write or later uncertainty retains power,
   emits the exact last-stage marker, and waits for reset.
5. Add a parent-side completion hook after generic secondary completion, then
   enable and verify MP2 DCM. Reject CPU8 disable and every CPU9 path. Publish
   cpu8-online-held only after that completion and DCM readback.
