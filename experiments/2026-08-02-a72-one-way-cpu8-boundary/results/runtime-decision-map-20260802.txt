Pre-boot statement
------------------

Hypothesis:
  The first natural, latched HPS CPU8 request will pass the already-proven
  pre-isolation sequence, clear external isolation once, validate the SRAM-LDO
  state, complete standard PSCI CPU_ON and generic secondary startup, enable
  DCM, and emit exactly one terminal `cpu8-online-held` marker. CPU9 and CPU_OFF
  remain forbidden.

Unique attributable evidence:
  The exact `gemini-a72-oneway-v1` terminal marker in live kernel output or
  retained console-ramoops, tied to this exact build identity and an automatic
  watchdog cycle. The success marker is emitted only after PSCI acceptance,
  generic secondary completion, `cpu_online(8)`, CPU9 absence, and successful
  DCM readback. Screen color or an apparent reboot is not kernel attribution.

Observation paths:
  1. Arm the direct USB/netcat live marker collector before manual boot2
     selection. It is read-only and optional because the twelve-second reset
     deadline may expire before USB becomes serviceable.
  2. Before manual selection, arm `scripts/collect-device-pstore` with
     `--wait-for-cycle`; after known-good Gemian returns, retain all pstore
     records without deleting them.
  3. On the returned Gemian boot, prove a changed boot ID, exact 2019 kernel,
     watchdog-class reset reason, CPU8/9 offline, unchanged boot2 checksum, and
     an inactive/unmounted live-GPT-resolved boot2.

Checkpoint(s) without one exact terminal marker, multiple conflicting terminal

Deployment boundary
-------------------

The installer may write only the exact full candidate to the live-GPT-resolved
inactive, unmounted, writable 16 MiB logical `boot2`. It requires the exact
rollback-candidate predecessor (or skips an already matching candidate), Good
battery health and capacity above 80%, a synchronized full write, matching
on-device and independent full-partition readbacks, staging cleanup, and clean
shutdown. It records the predecessor checksum and creates no new partition
backup. Primary boot, boot3, preloader, NVRAM, GPT, and whole-device writes are
outside authorization.
