Inference boundary
------------------
The restored natural-down value is written outside the instrumented public
Linux path. Retained firmware is the leading owner inference because PSCI off
and secure cluster teardown occur between the observed online and offline
snapshots, but the exact writer was not captured. The active private kernel is
hook-equivalent rather than source-identical, and the observer cannot record a
secure-side MMIO write. Do not promote the inferred firmware owner to fact.

Rejected branches
-----------------
- Linux clear-then-set isolation: invents an unobserved inverse and ownership.
- Isolation clear followed by userspace collection: holds an intermediate
  state far beyond the working path's 240-microsecond interval.
- Reuse public cpu_power_off_buck as rollback: it neither restores isolation
  nor provides a real SRAM inverse and can remove shared external power.

Decision
--------
There is no evidence-backed Linux isolation inverse. The next implementation
must use the already-proven pre-isolation rollback only. At or after an
isolation-write attempt it must retain power, reject retry, record the exact
last stage, and recover by reset. The smallest useful transaction proceeds
directly through SRAM-LDO and one standard CPU8 PSCI request with independent
readback and secondary-completion classification. CPU9 and CPU off remain
forbidden.
