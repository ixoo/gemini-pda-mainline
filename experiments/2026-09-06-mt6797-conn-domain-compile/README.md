# MT6797 CONN domain-data compile artifact

This offline experiment compiles one typed, experiment-local descriptor for
the future MT6797 CONN power island. It uses proposed local ID 12 and the
source-established fields: `conn`, `BIT(1)`, control offset `0x32c`, zero
SRAM request/ack masks, bus-protection mask `0x60000`, no clock, preclock or
parent, and `MTK_SCPD_KEEP_DEFAULT_OFF`.

The descriptor is compiled against the actual `struct scp_domain_data` and
`enum clk_id` extracted from the pinned provider after applying the existing
deferred-registration proposal. It is not added to
`scp_domain_data_mt6797`, `mt6797_data`, the match table, subdomains, the
public binding header or a onecell translator. It has no callback, probe,
registration, consumer, MMIO, resource, reset, firmware, device or runtime
path. No kernel patch is generated by this experiment.

Run from the repository root:

```sh
python3 -B experiments/2026-09-06-mt6797-conn-domain-compile/scripts/verify.py
```

The verifier fetches only the pinned public provider and binding files,
checks their identities, applies the pinned deferred-registration proposal in
a private managed temporary checkout, compiles the actual descriptor with
strict warnings and ASan/UBSan, runs its field fixture, and rejects mutations
that wire the descriptor into provider data, increase the registered count,
add a public consumer ID or change an existing binding ID. It invokes the
existing deferred-registration runner rather than copying it; that runner
covers OFF/ON/mixed/change/resource/init, generic-PM-disabled and normal
domain regression behavior. The verifier also sends a bounded handled SIGTERM
to a small worker path and records that its `verify-*` temporary directory is
removed during unwinding.

The recorded receipt is [`validation.json`](validation.json). The source and
proposal are experiment-only, synthetic/non-certifying material with no DCO
sign-off. This compile evidence does not establish CONN ownership, outer VCN
rail or CONMCU-reset sequencing, SPM-key authority, partial-transition
recovery, hardware behavior or Wi-Fi support.

There is intentionally no kernel patch, public binding change, provider
series/profile change or Buildbox artifact. Astra rejected those directions
because the incomplete generic callbacks and unresolved outer ownership would
make an otherwise unused ID misleading. Consequently Checkpatch and Buildbox
are not applicable to this nonregistered, experiment-local descriptor; the
receipt records the actual-type compile and the reused deferred-registration
host checks instead.
