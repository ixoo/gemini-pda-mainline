# Prepare the private Wi-Fi board record

The [normal-set profile](../2026-10-01-mt6797-normal-sets/README.md) can frame and submit source-identified configuration commands, but it has no kernel-side provider for the board's `WIFI` record. [Patch 0061](../../patches/proposals/0061-wifi-mediatek-prepare-private-board-record.patch) adds a standard `request_firmware` provider for `mediatek/mt6797/WIFI.storage`. It requires the complete 514-byte storage form, verifies the alternating add/XOR trailer and selected source-version predicate, and refuses record flags whose command branches are not implemented. It retains the original first 512 bytes for the NVRAM command and prepares only the four conditional power payloads established by the pinned source and [layout audit](../2026-09-05-mt6797-wifi-contract/CALIBRATION.md).

Preparation performs no HIF, firmware-command, DMA or radio operation. The provider has no caller in this profile. A future caller must retain the immutable record through submission, establish capability and board applicability, derive current cfg80211 policy, and prove the required shared-resource and packet lifetime. Neither checksum nor a compatible source version proves factory provenance, safe power limits or firmware application. Private calibration bytes and their record digest remain outside Git.

The [host result](results/host-validation.json) covers the exact header's synthetic branches, zero-on-refusal behavior and sanitizer run. The same parser accepted the independently verified private record in a private test without emitting its contents. A clean pushed-commit [Buildbox compile](results/build.json) passed and linked the four provider entry points. No new device candidate or Wi-Fi support claim follows from this compile-only profile.
