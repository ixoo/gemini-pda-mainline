# Temporary swap prerequisite — corrective protocol proposal

Status: preparation only. The frozen installer's `a53_no_swap` gate stays
unchanged. Its purpose is to keep the credential-bearing candidate's tmpfs
staging outside swap. No swap mutation, installer retry, shutdown or new boot
is enabled by this proposal. The current custodian retains custody with live
access paused until the coordinator admits a specific action.

The attended installation stopped before staging or writing. The first bounded
swap-specific probe returned nonzero and is not an accepted complete prerequisite.
Its partial evidence remains private; do not fabricate a completion marker or
repeat its consumed claim. The coordinator must review the retained evidence
and admit any specific missing-fact probe separately. This is an operational
review, not a request that the owner run commands or grant blanket permission.

The corrected [read-only probe](scripts/probe-swap-prerequisite.sh) distinguishes
an absent optional configuration file from a regular, bounded readable file,
unsafe type, read failure, invalid digest/size and observed change. Absence is
explicit metadata, never an inference that no swap manager exists. The final
same-boot check follows optional-file handling, including its absent branch.
No replay is admitted by this correction.

[Nine host test methods](scripts/test-swap-prerequisite.py) pass in 0.055 seconds,
covering absent/regular files, directories, FIFO, dangling and regular-file
symlinks, oversize/malformed input, read/hash failures and final-check ordering.
Only the extracted optional-file function runs against temporary host files;
the complete device probe is never executed by the tests. Bash syntax and
ShellCheck pass. Optional hashing is a bounded observation, not proof of an
immutable configuration snapshot or manager ownership.

## Required facts before admitting a mutation

- Same authenticated known-good Gemian boot, exclusive custody and no competing
  memory-heavy activity or installation. Use the existing dedicated SSH trust
  and key; no learning, fallback or connection retry.
- One exact active entry, identified from complete `/proc/swaps` records. Bind
  original spelling, canonical backing path, type, size, used amount, priority
  and held/checked file or device metadata. Resolve multiple systemd aliases to
  that one backing identity; aliases are not additional swap entries. Refuse
  extra entries or changed identity rather than invoking `swapoff -a`.
- Two memory/swap samples two seconds apart, plus a fresh check immediately
  before mutation. Require valid KiB units and
  `MemAvailable >= Used_swap + 65536 KiB + 1048576 KiB` in every sample.
  The 64 MiB allowance covers bounded installation preparation; 1 GiB remains
  OS headroom. Use the largest sampled swap usage and smallest available memory.
  Missing `MemAvailable`, falling below the margin or new swap allocation that
  invalidates it refuses. This is a conservative gate, not an OOM guarantee.
- Exact utility identities and effective restoration semantics. Preserve
  backing identity, options and priority; never infer discard or other options
  from `/proc/swaps`, which does not contain them. An absent fstab is absence,
  not proof that swap has no boot-time or runtime owner. Empty systemd fragment
  metadata also does not prove absence of a manager that could re-enable it.
- Review the existing owner/startup mechanism without changing it. A competing
  manager requires a separately reviewed plan; this scope does not stop,
  disable, mask or rewrite services. The normal known-good boot policy must
  remain capable of restoring the original configuration after a successful
  install/shutdown and later recovery.
- If the entry is zram, preserve its backing device and all configuration:
  no reset, resizing, format or compression-policy write. If it is disk-backed,
  ordinary resumed kernel swap I/O is expected on rollback; it is not an explicit
  raw/partition/firmware manipulation. Do not promise a generally running OS
  performs zero disk writes. No raw backing contents are captured by this plan.

Missing facts should be answered by a single explicitly admitted read-only
probe, bound to the recorded boot, with a 30-second transport ceiling and bounded
private stdout/stderr. Only the missing metadata/ownership fields belong in that
probe. Do not repeat already completed hardware or candidate checks to fill time.

## One temporary deactivation, then review

1. Freeze the exact swap path, utility bytes, backing identity, restoration
   command/options and admission before connecting. Record original priority
   and policy evidence privately. No actual live admission is generated by this
   document. A claim is consumed before the one mutation dispatch.
2. Within the unchanged boot/custody, recheck the entry and memory gate. Invoke
   only `swapoff -- "$EXACT_SWAP_PATH"` for that recorded entry. No `-a`, no
   other swap device, no fstab edit, no `mkswap`, no mount change and no partition
   substitute. The exact utility and argument vector must be frozen before use.
3. Capture its status and immediately inspect `/proc/swaps`, memory and boot
   identity. Success requires the exact entry absent, no other active swap and
   the same boot with sufficient headroom. Unexpected re-enabling refuses; do
   not keep switching swap off in a loop.
4. End this action and review its immutable receipt. There is no chained
   installer retry. Only the coordinator's subsequent installer admission uses
   the existing [install-boot2.py](scripts/install-boot2.py) and its unchanged
   staging/live-GPT/power/full-readback/shutdown gates. No keyboard, eMMC or radio
   observation is added to the first baseline.

Bound the local transport to 30 seconds and permit at most one deactivation
call. A local timeout does not prove the remote kernel operation stopped.
Uninterruptible kernel work cannot be given a guaranteed userspace reap bound.
On timeout, disconnect, missing final framing or uncertain termination, classify
the action as indeterminate, stop all dependent actions and preserve the claim.
Do not launch a concurrent restoration, another swapoff, installer or reboot.
An explicitly admitted read-only reconciliation must first establish the same
boot, current exact swap state and termination of the prior operation.

## Abort and restoration

Before a mutation is admitted, freeze one rollback action for the original
entry. For an explicit nonnegative priority, use the recorded priority with
`swapon --priority "$ORIGINAL_PRIORITY" -- "$EXACT_SWAP_PATH"` and only other
verified original options. For an automatic negative priority, restore the
original default-priority semantics without inventing a positive priority;
verify the resulting priority against the original record. If the exact utility
cannot reproduce the required configuration, do not admit deactivation.

- If the pre-mutation gate fails, no swap state changed and no rollback runs.
- If swapoff fails and the original entry is still active with matching
  configuration, record that result; do not issue a redundant swapon.
- After confirmed successful deactivation, an abort before installer staging
  restores only the original entry, once, and verifies its identity, priority,
  options and sufficient memory. Never format or reset its backing storage.
- After installer staging has begun, restoration must wait until the frozen
  installer's cleanup is complete and no credential-bearing staging file or
  writer remains. Re-enabling swap while that state is unresolved defeats the
  safety gate. Do not erase unique evidence to satisfy cleanup.
- A successful verified installation and shutdown ends this live Gemian state.
  Its unmodified normal startup policy supplies restoration on later Gemian
  boot; no swap modification is added to the first-baseline confirmation probe.
- Failed or indeterminate restoration stops the session with custody retained.
  Do not reboot, retry, alter priority heuristically or release the device as
  restored. Record the unresolved state and let the coordinator choose recovery.

A future one-shot action wrapper must implement the admitted rollback on handled
abort after a confirmed state transition. Traps alone do not establish rollback
after transport loss or an in-flight kernel call; those follow the explicit
indeterminate/reconciliation branch above. No such wrapper is implemented or
executed by this protocol. Runtime readiness and queue changes remain with the
coordinator; private evidence stays in the attended-session archive.
