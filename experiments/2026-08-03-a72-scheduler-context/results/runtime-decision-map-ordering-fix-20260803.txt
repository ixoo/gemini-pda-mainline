Hypothesis and unique observation
---------------------------------

The exact pair-v6 parent passed twice. Attempt 1 did not evaluate scheduler
work because terminal work raced the inherited worker's final publication.
The corrected pair-v7 leaves that worker unchanged, snapshots the complete
published parent state in the sample-3 terminal worker, and starts scheduler
work only inside the exact parent-pass branch. It then creates two
normal-priority kernel threads, binds them before first wake to CPUs 8 and 9,
dispatches them in task context, rendezvouses them concurrently, completes
identical bounded integer workloads, stops both threads, and publishes one
isolated terminal before the inherited watchdog recovery.

Decision branches
-----------------

PASS
  Require adjacent complete pair-v6 and pair-v7 pass terminals, every exact
  scheduler lifecycle field and hash above, automatic recovery, no panic/BUG/
  Internal error/Call trace/timeout/SError/lockup, CPUs 8/9 offline after
  recovery, and unchanged boot2. One exact repeat is then earned. Do not enable
  CPU_OFF.

PAIR-V7 FAULT OR SCHEDULER MISMATCH
  Any `gemini-a72-pair-v7 result=fault`, `parent_pass=0`, nonzero create/error/
  stop result, incomplete wake/wait/done/rendezvous value, wrong CPU, missing
  task context, or wrong hash is a reject. Record every field. Do not repeat
  unchanged; use the first failing phase and coordinate for the next change.

INHERITED-PARENT FAILURE
  Any pair-v6 value outside its exact pass contract is a regression. Do not
  evaluate scheduler success or repeat unchanged.

AUTOMATIC RESTART WITH NO PAIR-V7
  Distinguish terminal-not-reached from evidence loss using changed-cycle
  pstore, the complete pair-v6 line if present, watchdog reason, and console
  continuity. Repeat only if a new independent observation can distinguish
  those classes.

NO AUTOMATIC RESTART OR LOST RECOVERY
  Treat as a safety failure. Recover through known-good Gemian, preserve
  pstore, verify boot2 identity, and do not repeat unchanged.

Success boundary
----------------

One pass establishes only bounded task-context dispatch, affinity, completion,
and cleanup for this exact two-thread oracle. A second exact pass establishes
repeatability. Neither result authorizes CPU_OFF, removes the HPS veto, proves
production scheduling, load, thermal, OPP/cpufreq, or suspend stability, or
makes CPUs 8/9 production-online.
