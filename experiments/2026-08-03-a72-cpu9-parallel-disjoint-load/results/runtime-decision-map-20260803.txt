Hypothesis and unique observation
---------------------------------

The exact pair-v5 parent passed repeatedly. Pair-v6 preserves every inherited
startup, HPS, scalar-coherency, and multiline gate, then dispatches CPUs 8 and
9 concurrently. Each CPU writes its disjoint half of a 64 KiB, 1,024-line
working set, rendezvouses through finite barriers, and verifies its peer's half
for 128 rounds.

The only positive result is one complete `gemini-a72-pair-v6 result=pass` line
with the exact inherited pair-v5 pass fields plus:

  pl_reported=1 pl_rounds=128 pl_lines=1024 pl_words=8
  pl_cpu8=8 pl_cpu9=9 pl_error8=0 pl_error9=0
  pl_done8=128 pl_done9=128
  pl_ready=256 pl_written=256 pl_verified=256
  pl_hash8w=X pl_hash8r=Y pl_hash9w=Y pl_hash9r=X
  pl_bad_round=0 pl_bad_line=0 pl_bad_word=0
  pl_expected=0000000000000000 pl_actual=0000000000000000

X and Y must be nonzero 16-digit hexadecimal values and cross-match exactly.
The same line must retain the complete pair-v5 HPS, 1,024-round scalar, and
64-round multiline pass contract. Screen color or automatic restart alone is
not evidence.

Observation sequence
--------------------

1. In ordinary Gemian, run the reviewed installer. It must resolve exactly one
   live-GPT boot2, prove it inactive and unmounted, record predecessor checksum
   without a fresh backup, write only when different, verify full-partition
   readback, remove temporary copies, and shut the device down cleanly.
2. Arm `scripts/collect-device-pstore --target gemini@192.168.1.50 --wait-for-cycle`.
   The USB/netcat collector is read-only and secondary.
3. Physically select boot2 once. Expected visible behavior is the inherited
   bounded automatic watchdog restart into ordinary Gemian.
4. After recovery, require changed-cycle continuity, watchdog-class recovery,
   CPUs 8/9 offline, inactive/unmounted boot2, and full checksum
   `0beead0b00485ad18333aca4d688fcd549c813113b7ec0554a6761c7147b17fb`.
5. Classify only the attributable changed-cycle pstore/console evidence.

Decision branches
-----------------

PASS
  Require the complete pair-v6 terminal, all inherited gates, exact parallel
  counts and hash cross-match, automatic recovery, no panic/BUG/Internal error/
  Call trace/timeout/SError/lockup, CPUs 8/9 offline after recovery, and
  unchanged boot2. One exact repeat is then earned. Do not enable CPU_OFF.

PAIR-V6 FAULT OR PARALLEL MISMATCH
  Any `gemini-a72-pair-v6 result=fault`, nonzero `pl_error*`, incomplete round
  or barrier count, hash cross-mismatch, wrong CPU, or nonzero mismatch field is
  a reject. Record every terminal and recovery field. Do not repeat unchanged;
  use the first failing phase and coordinate for the next source change.

INHERITED-PARENT FAILURE
  Any pair-v5 HPS, scalar, or multiline value outside its exact pass contract
  is a regression. Do not evaluate parallel success or repeat unchanged.

AUTOMATIC RESTART WITH NO PAIR-V6
  Distinguish terminal-not-reached from evidence loss using changed-cycle
  pstore, earlier terminal state, watchdog reason, and console continuity.
  Repeat only if a new independent observation can distinguish those classes.

NO AUTOMATIC RESTART OR LOST RECOVERY
  Treat as a safety failure. Recover through known-good Gemian, preserve pstore,
  verify boot2 identity, and do not repeat unchanged.

Success boundary
----------------

One pass establishes only bounded concurrent integrity for this exact 64 KiB,
128-round disjoint-load oracle. A second exact pass establishes repeatability.
Neither result authorizes CPU_OFF, removes the HPS veto, proves production load
or thermal stability, or makes CPUs 8/9 production-online.
