Boot observation
----------------

Orion reached its console and USB-only root shell. The DVFSP access-controller
consumer initially deferred with `-EPROBE_DEFER` while its supplier performed
the intentional 45-second late validation. At approximately 48.1 seconds:

- the handoff supplier entered `ready`;
- its consumer-held and consumer-cleanup clock validations passed;
- the I2C6 probe then failed with `-EINVAL`;
- `/sys/bus/platform/devices/1100e000.i2c/driver` was absent;
- the driver-specific `handoff_status` attribute was absent.

No I2C6 hardware conclusion follows from this attempt because the adapter was
removed before any transfer.

One-shot disposition
--------------------

The first host collector invocation failed locally while expanding its remote
program because its placeholder check also matched intentional transcript
markers. It did not create an output directory, connect to the device, mount

made one connection. The remote pre-trigger program exited before emitting its

Attributable root cause
-----------------------

The exact Orion build reaches `mtk_i2c_orion_init()` only after
`i2c_add_adapter()` and both successful handoff clock checks. Its only
Orion-specific `-EINVAL` then compares:

`of_node_full_name(i2c->dev->of_node)` against `/i2c@1100e000`.

In the pinned Linux 7.1.3 source, `populate_node()` assigns
`device_node.full_name` directly from `fdt_get_name()`. For this root child the
stored value is therefore the bare node name `i2c@1100e000`, not the absolute
path. The comparison deterministically fails and the error path removes the
adapter. The boot DT itself still contains the intended root-level I2C6 node
and validated access-controller relationship.

Next decision
-------------

Use `of_find_node_by_path("/i2c@1100e000")`, compare the returned node pointer
to the probed node, and release the reference with `of_node_put()`. Retain the
special-compatible and non-null handoff checks. Give each failed identity check
an attributable error message. A next boot can then distinguish successful
I2C6 binding from a new failure and, only after all preconditions pass, run the
fixed FIFO/DMA diagnostic exactly once.
