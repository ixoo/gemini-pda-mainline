# Source-only vmlinux-to-elf kernel-database provenance audit

- **Outcome:** identify and freeze the exact hash-bearing installed package
  source/data behind `vmlinux_to_elf.kernel_db.database.KernelVersion`, while
  explicitly excluding the unverified generated bytecode entry from evidence
  and future execution. Determine the database path/open/effect contract and
  whether a later parser run may admit the exact metadata lookup under
  source-forcing and effect guards. No package/parser import or private-kernel
  access is part of this audit.

  `5b3dc98ffbaccd36e5f3acfd0c98ffe4dcadfd19`. The excluded RECORD-gate
  predecessor is pinned as WORK_ITEM
  `71fd7a672b362dd5ead4597da3c9c5070112c6b01cb18524e3fd67a0fb25d165`,
  inputs `13485ddf638a4544065e6f05a404aa8301f7c4bd2319ecdbea96cafea6e84758`
  and validation
  `364cc9ed5c031a5d97ae049321309efcbdf4eacf85c70e9a82a3d376edd5b882`.
  Verify these first. Do not reuse unpublished inventory or inspect its empty
  private work child.

  3.12.3, METADATA
  `133b5a6b7fab8081a7c201f2fc63b8a2d7a215475c423c8fe3938aff6a708c43`,

- **Model route:** `gemini_specialist`, `gpt-6-astra`, medium for provenance

- **Owned scope:** create only this experiment's `README.md`, `inputs.json`,

- **Private-data exclusion:** run only through `./scripts/dev-vm re-shell`.
  Do not locate, hash, open or access Image.gz, Image, vmlinux, reconstruction
  diagnostics, prior parser output or other private kernel content. Raw audit
  logs remain in a fresh mode-0700 child. This audit reads installed
  open-source package material only.
- **Two-class RECORD gate:** after verifying parent/METADATA/RECORD/Kallsyms,
  enumerate exactly the four RECORD entries below
  `vmlinux_to_elf/kernel_db/`. Resolve without following symlinks and require
  every path below the distribution root. Exactly one entry may lack digest
  and size, and it must be the regular generated cache path
  `vmlinux_to_elf/kernel_db/__pycache__/database.cpython-312.pyc`. Record its
  relative name and both missing fields only; do not hash, stat beyond
  regular-file/path containment, read, copy, load or treat it as evidence.
  Every other entry must have a RECORD SHA-256 and size; decode and exactly
  match both before content inspection. Refuse any other empty field, cache
  entry, file-count drift, symlink or path escape.
- **Verified-content bound:** among the three hash-bearing entries, permit at
  most two `.py` files and exactly one database/data file. Record their
  distribution-relative paths, hashes, sizes and roles. Inspect only these
  verified files plus the pinned Kallsyms source. Never import or compile them.
  Set `PYTHONDONTWRITEBYTECODE=1`; no new cache file may appear anywhere under
  the distribution or fresh work child.
- **Static source trace:** trace the direct `KernelVersion` import, model
  definitions, database path expression, connection construction/flags/pragmas,
  import-time statements, schema creation/migration hooks, potential
  download/network/subprocess paths, cleanup and the exact
  `KallsymsFinder.extract_db_information()` `select().where(...)` field/result
  path. Do not inspect ORM or other dependency source. Return unresolved if
  complete behavior requires dependency-source expansion, runtime import or a
  dynamically selected database path.
- **Immutable database inspection:** only if static tracing identifies the one
  verified data file as SQLite, open that exact file once through an immutable
  `mode=ro` URI and enable query-only mode. Permit header validity,
  `sqlite_master` table/index/view names and SQL definitions,
  `PRAGMA table_info`, `user_version`, current `journal_mode`, foreign-key
  metadata and row counts solely for the directly traced models. Do not emit
  row values, URLs, kernel releases or bulk content. Hash and stat all three
  verified entries before and after. Any content/size/mode/mtime change or new
  journal/WAL/temp/cache file refuses the result. Do not copy the database.
- **Future source-forcing requirement:** because the installed cache entry is
  unverified, no later contract may rely on ordinary cache discovery. A
  conditional admission must require a fresh empty private
  `PYTHONPYCACHEPREFIX`, `PYTHONDONTWRITEBYTECODE=1`/`-B`, exact source and
  module-origin hashes, an absent cache artifact before/after, and active
  proof that the verified `.py` source—not the installed `.pyc`—supplied every
  admitted package module. If the audit cannot state a fail-closed way to prove
  that source selection, its verdict must require bypassing the package import.
- **Effect verdict:** admit the metadata query for a future guarded parser run
  only if the complete verified source path reads existing rows from the one
  frozen local database, has no import/query schema mutation or reachable
  acquisition action, and all selected model/database identities are exact.
  Generic ORM behavior is not proven by this audit; future execution must add
  network/DNS/subprocess and filesystem-write sentinels, exact pre/post hashes,
  a read-only database connection/path check and zero unexpected file opens.
  Logging or reading a stored URL is not itself a download; invoking it is
  forbidden.
- **Bound:** one installed distribution, one pinned RECORD, four enumerated
  entries, one excluded bytecode path, three hash-bearing files, at most two
  Python sources, exactly one data file, one immutable SQLite inspection and
  one static caller/model path. No bytecode hash/use, package/parser import,
  ORM query, compilation, dependency-source expansion, private kernel/prior
  output, instruction analysis, device, network or build.
- **Acceptance predicates:** independently establish (1) parent/distribution
  identities; (2) exact four-entry partition into one excluded cache and three
  verified files; (3) complete source/model/database path; (4) import/open/
  schema/acquisition effects; (5) immutable schema/count and unchanged-state
  facts; (6) exact selected-query semantics; (7) fail-closed future source
  selection; and (8) conditional query admission or required bypass with exact
  guards. A bounded negative result is acceptable.
- **Refusal and validation:** reject identity/RECORD drift, more/fewer entries,
  any second/unexpected unhashed entry, bytecode read/hash/use, symlink/path
  escape, verified file mismatch, source/data count drift, package import or
  compilation, new cache/journal/temp file, database state change, query
  execution, dependency-source expansion, dynamic path, hidden acquisition,
  private-kernel access, row-value publication, inferred no-effect/source-use
  claim, mutable expected digest, private path/content or authority expansion.
  Freeze JSON evidence before writing the verifier. Normal and optimized modes
  must use active checks and mutations for every identity, entry class,
  source/data path, schema/effect/query/source-selection and authority class.
- **Rights and privacy:** publish only hashes, relative paths, sizes, bounded
  schema/count metadata and independently worded source behavior. No bytecode

  proprietary content, credentials, serial/IMEI/calibration data or private

- **Hardware/build effects:** none. The device remains known-good Gemian with

- **Stop/escalation:** stop on any identity/entry/path mismatch, need to read or

- **Handoff:** exact parent/distribution identities; four-entry partition;
