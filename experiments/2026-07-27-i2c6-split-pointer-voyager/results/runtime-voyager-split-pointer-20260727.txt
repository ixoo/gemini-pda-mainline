Observation
-----------

Both protocol-valid split reads returned success and replaced distinct RX
prefills with their respective preceding TX pointers:

`3c -> 06` and `a6 -> 47`.

All four I2C6 counters advanced exactly by four while the boot ID, CPU set,
handoff, and USB service state remained unchanged.

Analysis
--------

The exact per-pair pointer correlation proves that a hardware-visible write
replaced each RX prefill with its immediately preceding TX pointer. It
strongly favors controller/APDMA TX-pointer residue but does not identify the
physical writer. The datasheets explicitly permit the second START after
STOP, so the result is not explained by an invalid split-read protocol.

The result does not locate the defect within FIFO state, APDMA direction,
address or length programming, or completion/coherency. It does establish a
stronger boundary than counters alone: two distinct pointer bytes appeared in
the corresponding RX buffers.

The expected DA9214 live tuple `d0,c0` was not observed. Values `06,47` are
pointer residue, not DA9214 register contents.
