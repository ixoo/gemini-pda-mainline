# Pruning pass, 2026-10-24: the measurement surface after the equivalence boot

Owner direction: once the tree is verified, take inventory of
measurement-only profiles, fragment lines and options and retire the ones
whose questions are answered, in one reviewable commit. This record is
that list. Retired files stay in the git history; no experiment record
is changed except two links that pointed at retired files.

  board, service, Bluetooth and STP compile profiles are outside this
  pass.
- Proposals `0262` (TX-completion rate record, option
  `CONFIG_MT6797_TX_DONE_RATE_RECORD`, off by default) and the receive

## Options

The first draft of this record listed eleven driver options as compiled
into no remaining profile. Checked against the applied tree, none of
them exists any more: proposal 0234 (the collapse of the experiment build
arms) had already removed them, and the names came from the text of
superseded proposal patches. The driver's Kconfig today holds eighteen
`MT6797_*` symbols; sixteen are selected or set in the lifecycle build,
`CONFIG_MT6797_HIF_DMA_RX` waits for the receive-direction boot, and
`CONFIG_MT6797_TX_DONE_RATE_RECORD` is the measurement record kept for
rate boots. No driver-side removal is outstanding from this pass.

## Second increment (2026-10-25): the test and script families of retired profiles

Method: every host-test runner was run against the live driver tree in the
development VM (57 runners: 19 pass, 12 fail to build or assert, 26 refuse
for want of a parent and candidate tree, being differential tests of one
proposal). A test file was a retirement candidate when its name or
contents belong to a retired run family (the CCMP, GTK, P1/P2, I50, S1,
SSH-D and snapshot runs) or name a retired profile, and it was kept when a
runner that mentions a live proposal names it, or when live tooling (the
harness, the hosts directory, the repository checks) names it.

Counts: 173 candidate test files, 22 kept, 151 deleted; 46 scripts outside
`tests/` referenced retired profiles, 41 deleted (the CCMP, GTK, P1/P2 and
I50 build and install scripts and the four retired transmit-arm
validators of this experiment), 5 kept (the live session adapter and the
single build scripts of three older experiments, which are those
experiments' own chronology). 192 files in all.

No live proposal lost its pin: the fourteen lifecycle proposals mentioned
only by the differential runners (0196–0200, 0204–0210, 0212–0213) keep
those runners and the sources they name, which still need a parent and a
candidate tree to run. The twelve runners that fail against the live tree
(the phase-B join peer, HIF, handoff, regulatory-close, submit and rearm
tests, the native HIF and PM-contract tests, the Gemian reference tests)
are stale pins of live code paths; they are listed here as repair-or-retire
work and were not deleted by this increment.

Repository check wall time, before and after: 16.6 s and 17.2 s on the
same host. The premise that the corpus cost check time was wrong: the
check was already fast, and the deletion bought clarity, not time. The
per-boot cost sits in the prepare step and in what has to be read to
decide the next boot, not in the checks; the test corpus is not where
speed is to be found. The twelve runners that fail against the live tree
are kept as debt, to be repaired or retired deliberately; a "kept" note is
not a fixture anyone runs.
