Findings
--------

1. A production profile is forbidden from declaring current target evidence.
   late_profile_runtime_fields_empty() rejects any profile-owned observed
   MPIDR, MIDR, REVIDR, target_cap, target_policy, system_cap, runtime binding,
   or evidence identity. arm64_prepare_late_cpu_profile() blocks a profile
   that declares RUNTIME origin. These are deliberate provenance gates.

2. The architecture runtime collector is deliberately target-empty before the
   first request. late_runtime_evidence_storage_complete() requires target
   CPU identities, expected/observed target values, and target_cap records to
   remain zero. The current collector adds only the exact running image
   binding, current system capability state, and current policy replicated for
   both future targets.

3. The planner nevertheless still reads evidence.target_cap[] directly.
   The MT6797 classifier uses it for GICv5 legacy, ICH_HCR_EL2_TDIR, cache
   mismatch, Spectre-v2, Spectre-v4, and Spectre-BHB. The effect planner uses
   it for Spectre/BHB decisions. The HWCAP planner requires the coarse
   ID_REGS_VALID bit and then reads the complete 47-field register image.
   Production leaves these records empty, so all six named capabilities stay
   unresolved and planning remains fail-closed.

4. A truthful pre-request current-target producer cannot exist in this order.
   READY is required before the admission controller may request CPU8, while
   CPU8 register, GIC interface, and CPU-local SMCCC outcomes can be observed
   only after CPU8 executes. Calling those values current-mainline target
   evidence before the request would be circular. Copying the prior Gemian
   capsule into target_cap would instead violate findings 1 and 2 and the
   documented provenance rule.

5. The separate expected_pair is the legitimate pre-request CPU contract.
   Its 28 named validity fields cover two capsule identities, two MPIDRs, MIDR,
   REVIDR, CNTFRQ, raw CTR, CLIDR, seven captured AArch64 ID registers, and
   twelve captured AArch32 ID registers. It is explicitly prior-cycle data and
   has no active production initializer. It cannot truthfully set the coarse
   current ID_REGS_VALID bit because 23 register-image fields remain
   unmeasured.

6. Current consumers divide into three ownership classes:

   - Expectation plus current-system inputs: cache mismatch can use exact
     expected raw CTR/CLIDR and current system CTR/strict mask. Spectre-v2 and
     Spectre-v4 have exact expected PFR0/PFR1 feature fields, but their CPU-local
     WA1/WA2 outcomes are not available before target execution. BHB has exact
     expected PFR0 and MMFR1, but ISAR2.CLRBHB is unmeasured.
   - Missing target-entry/current-controller inputs: GICv5 legacy additionally
     needs unmeasured PFR2.GCIE plus ICC_IDR0, ICC_SRE, and SRE usability;
     ICH_HCR_EL2_TDIR additionally needs current hyp mode and an ICH_VTR
     source/status/value.
   - Current source has no planning consumer for target ASID, page granule, or
     VA-width validity. Those bits are schema/canonicalization/fixture fields,
     so their blockers must not be cleared until an actual consumer and owner
     are defined.

Decision
--------

classification=confirmed-pre-request-provenance-cycle

Reject a new pre-request "current target-cap producer". It is impossible in
the existing READY-before-CPU-request order and would either invent an
observation or erase the expected/current provenance boundary.

Logical slice 6 is instead one architecture-owned, source-only planning-input
separation:

1. Introduce a field-valid expected-target planning view derived only from
   expected_pair. It must remain distinct from evidence.target_cap and retain
   the prior-cycle provenance in canonical identities.
2. Migrate pure register and HWCAP planning to named expected fields. An
   unmeasured field is unavailable, never an observed zero. HWCAP intersection
   must conservatively omit a capability when its target field is unavailable.
3. Permit only decisions whose complete inputs are already owned, beginning
   with raw/effective CTR and static MIDR/range classifications. Keep GIC/hyp,
   WA1/WA2/WA3, and unmeasured modern-ID decisions explicitly unresolved until
   a separate current owner or an audited conservative entry constraint exists.
4. Preserve every production runtime-empty gate. Do not add an active expected
   pair, clear blockers, publish READY, request CPU8 or CPU9, retry, call
   CPU_OFF, build a candidate, or take a device action in this slice.
