## Question

The 2026-10-03 review found the plan buried in chronology, the experiments
index 45 percent incomplete, profiles accumulating one per question, and
hygiene checks that only looked at changed files. The September cleanup had not
held: `docs/ROADMAP.md` went from 262 lines on 2026-09-04 to 1,679 lines on
2026-10-04. What is the smallest set of changes that makes the next step
findable in one page, keeps the records complete, and stops the drift from
recurring?

## What changed

**Roadmap.** `docs/ROADMAP.md` now states the order of work in under 200
lines: where things stand, the next device boots in order, offline work, the
rules that prevent re-accretion, parked items, gates and milestones. The
previous file is kept verbatim as [ROADMAP_2026-10-04.md](ROADMAP_2026-10-04.md)
with its link paths adjusted, and the detailed per-block plan derived from the
2026-10-04 reverse-engineering records moved to
[AFTER_WIFI_GAPS.md](../2026-10-03-project-review/AFTER_WIFI_GAPS.md). The
section anchors older records link to are kept in the new roadmap and point
readers to the historical file.

**Experiments index.** `experiments/README.md` had 294 of 536 directories
listed. It is now a table generated by the new `scripts/experiments-index`
from each record's title and Status field, covering every directory, and
`scripts/check-repository` fails when the table is stale or a directory has no
README. Six directories had no README and received a minimal one pointing at
their original files. Twenty-five records still marked `running`, `collecting`
or `in progress` five to ten weeks after their last commit were closed as
`superseded`, `parked` or `completed`, each with a note naming this record.
`experiments/TEMPLATE.md` adds `parked` to the status vocabulary. Older READMEs
whose Status text does not start with a vocabulary word show as `unstated`;
they were not edited.

**Hygiene.** 416 tracked files carried the owner's home-directory paths or the
Gemian LAN endpoint, all under `experiments/` plus
`docs/hardware/partition-backup.md`. Home paths are now `~/` and the endpoint
is the placeholder `GEMIAN_HOST`; the fleet configuration outside the
repository owns the real value. `scripts/check-repository` now scans the whole
tracked tree for personal paths and cloud tokens, not only changed files, and
exempts the device, Buildbox and placeholder user names. The GitHub workflow
runs on push to `main` and on pull requests again; it had been manual-only since
2026-09-06. `.gitignore` refuses key material locally.

**Planning metadata and tracker.** `project/` kept only the device-session
template. The experiment queue, workstream registry, upstream-topic inventory,
label and milestone inventories and the issue backlog were last meaningful in
September and are replaced by the roadmap; their final copies are at
[commit 164c2d3f](https://github.com/ixoo/gemini-pda-mainline/tree/164c2d3f/project),
and the documents that linked to them now point there. GitHub issues #1–#30,
untouched since 2026-07-11, were closed on 2026-10-05 with a pointer to the
roadmap and the historical backlog; #34 went from P0 to P2 as a watch item.

## Profile retirement

The manifest carried 273 profiles, 112 series files and 262 config fragments,
one set per question ever asked of the device. The audit for this record kept
12 profiles that the roadmap or the scripts still need and retired the other
261 together with the 103 series files and 230 fragments only they referenced.
Every retained profile passes `validate-manifest-series`.

Keep: `full`, `handoff`, `usbdiag`, `usbdiag-clkignore` (named by
`scripts/kernel` and `scripts/dev-vm`), `mt6797-a53-service-facilities` (the
A53 foundation), `mt6797-a53-c1-compile` (boot C1),
`mt6797-a53-stp-task-routing-compile` (boot C3, superset of the WMT line),
`mt6797-a53-wifi-scan-tuning-sample` (the Wi-Fi tip for Phase A),
`mt6797-infracfg-current-mainline`, `bq25890-irq-compile`, `mt6397-rtc-wake`
and `mtk-sd-pinctrl-compile` (upstream topics). The lists are
[retired-profiles.txt](retired-profiles.txt) and
[unreferenced-inputs.txt](unreferenced-inputs.txt). Thirteen patches are now
referenced by no retained series (proposal 0085, the A72 power sequence
0093 and the DA9214 legacy regulator patches 0096 and 0104–0113); they stay in
`patches/` as evidence until the parked work is decided.

Applied on 2026-10-05 with the owner's explicit approval: the top-level
`patch_series` fallback now names `patches/series` (it pointed at a thermal
experiment prefix), the retired Gauss profile protection left
`scripts/test-manifest-series-invariant`, the three retired profile names used
as examples in `docs/BUILDBOX.md` were replaced, and the 28 experiment links to
deleted series or fragments point at commit `164c2d3f`. Retired definitions
remain in Git history; nothing booted or validated changes identity.

## Validation and limitations

`./scripts/check-repository` with the new tree-wide scan and index check,
`scripts/experiments-index --check`, `scripts/validate-manifest-series`,
`git diff --check`, shell syntax and ShellCheck for the changed test script, and
the Markdown link check over every changed file. No kernel build, checkpatch,
DT schema check or device action was part of this record; nothing here changes
a build input or a candidate.
